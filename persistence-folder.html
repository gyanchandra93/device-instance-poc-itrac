What this folder does

The persistence/ folder saves Device Instance Utility work in LocalStorage (scoped by user + project), then restores it when the page reloads. On restore it merges the draft with the latest API data, recreates deleted non-PPM materials / templates when possible, and pushes cumulative edits back to the API.

A
Mode A — hydrate on load / refresh Read LS → reconcile materials → recreate orphan non-PPM → reconcile templates → recreate orphan templates → hydrate UI → sync merged values to API.
B
Mode B — write-through while editing After a successful hydrate, debounce (~300ms) and rewrite the draft whenever materials / templates / instances change.
C
Clear after Create All success Wipe the LS draft so the next editing session starts clean.
Orchestrator hook

useDeviceInstanceDraftPersistence.ts

React hook that owns the full draft lifecycle. Presentational components never talk to LocalStorage directly — this hook coordinates storage, reconcile, orphan recreate, and Mode A sync.

Functions

useDeviceInstanceDraftPersistence(...)
exportedhook

Main entry. Takes current API rows, session state, and callbacks (hydrateFromDraft, replaceMaterialsAndTemplates). Returns reconcileAfterMaterialsRefresh and clearDraftAfterCreateAllSuccess.

showSyncFailureToasts(...)
internal

Shows sticky error toasts for materials / templates that failed Mode A API sync, asking the user to refresh and retry.

runModeASync(...)
internal

Calls syncDraftToApi. On failure: keeps the LS draft intact, pauses write-through, reverts failed UI rows to API values, and shows toasts. On success: returns the usage-adjusted materials/templates.

hydrateSessionFromDraft()
internal

Full Mode A pipeline on page load (runs once when API data is ready). Reads draft → reconcile materials → recreate orphan customs → reconcile templates → recreate orphan templates → prune invalid GI keys → hydrate UI → write cleaned draft → Mode A sync.

reconcileAfterMaterialsRefresh(freshApiMaterials)
returned

Same idea as Mode A, but triggered after “Refresh Materials”. Builds a draft from the current session, reconciles against the fresh API materials list, remaps/prunes template device FKs, then syncs again.

clearDraftAfterCreateAllSuccess()
returned

Clears the LocalStorage key after Create All succeeds and re-enables write-through.

Guard refs matter: hasHydratedRef (once), isHydrationRunningRef (no overlap), allowWriteThroughRef (Mode B only after successful Mode A).
LocalStorage I/O

draftStorage.ts

Thin, safe wrapper around window.localStorage. Builds the key, reads/writes JSON, validates shape, and never throws to callers.

Functions

Returns deviceInstanceUtility_{userId}_{projectId}, or '' if user/project is missing (callers must no-op).

isRecord / parseMaterialEntry / parseTemplateEntry / parseInstanceEntry / parseDraft

Defensive parsers. Drop invalid entries; tolerate older drafts missing newer fields (e.g. isCustom snapshot fields default safely). Wrong version → null.

clearDeviceInstanceDraft(projectId)
exported

Removes the LS key. Swallows storage errors.

hasDeviceInstanceDraftContent(draft)
exported

True if any of projectMaterials / groupTemplates / groupInstances has keys.

createEmptyDeviceInstanceDraft
exported

Alias of EMPTY_DRAFT — fresh mutable empty draft object.

Snapshot builder

buildDraftFromState.ts

Converts live React session state into the minimal draft shape stored in LocalStorage. Derived display fields (Used, Remaining, names already resolved elsewhere) are omitted.

Functions

buildDraftFromState({ materials, templates, instances, subclassItems })
exported

Builds DeviceInstanceUtilityDraft:

  • Materials — stores subclassId (name→id), override, hide, and non-PPM snapshot fields needed for orphan recreate.
  • Templates — parent fields + devices (including friendly names / sortOrder).
  • Instances — only stores rows where Group ID / Group Name was customized; drops keys whose template/index is out of range.
GI overlay

applyInstanceDraft.ts

Applies saved Group Instance customizations (renumber / manual Group ID / Group Name) onto auto-derived instance rows after templates produce them.

Functions

applyInstanceDraft(instances, groupInstancesDraft)
exported

For each instance key {templateId}:{instanceIndex}, overlays custom groupId / groupName when the draft flags say so. Leaves auto-generated values alone when no draft entry exists.

Merge LS + API

reconcileMaterials.ts

Merges latest API Project Materials with draft overlays. LocalStorage wins for subclass / override / hide. Missing PPM devices are pruned; missing non-PPM devices become orphan recreate candidates.

Types

OrphanCustomMaterialCandidate / ReconcileMaterialsResult
exported

Result shapes returned by reconcileMaterials.

Functions

canRecreateCustomMaterial(entry, subclassItems)
internal

True only for custom rows with description/make/model, valid subclass, and ppmQty > 0.

reconcileMaterials({ apiMaterials, draftMaterials, subclassItems })
exported

Returns:

  • materials — API rows with LS overlays applied
  • removedDeviceIds — PPM (or unrecreatable) ids to prune from GT
  • orphanCustomCandidates — non-PPM rows to recreate
  • nextDraftMaterials — cleaned draft map (orphans still pending recreate)
Merge LS + API

reconcileTemplates.ts

Same reconcile idea for Group Templates. LS wins for reference / description / parent subclass / instances / friendly names. Devices pointing at missing materials are dropped. Templates that exist only in LS become orphan recreate candidates (if they still have valid devices).

Types

OrphanTemplateCandidate / ReconcileTemplatesResult
exported

Result shapes for template reconcile + orphan handoff.

Functions

filterDevicesAgainstMaterials(devices, materialIds)
internal

Keeps only devices whose materialId still exists; reindexes sortOrder.

toUiDevices(devices)
internal

Maps draft device entries into UI GroupTemplateDevice objects.

reconcileTemplates({ apiTemplates, draftTemplates, materials, subclassItems })
exported

Overlays LS onto API templates; collects orphan candidates for templates whose API id is gone but still have remaining devices.

remapInstanceDraftKeys(groupInstances, previousTemplateId, nextTemplateId)
exported

When an orphan template is recreated with a new id, rewrites GI draft keys from oldId:n → newId:n.

Orphan recreate

recreateOrphanCustomMaterials.ts

Recreates non-PPM materials that were in LocalStorage but deleted on the API, then remaps old device ids → new ids in the draft and in Group Template device FKs.

Functions

recreateOrphanCustomMaterials({ projectId, orphans, subclassItems, createCustomMaterial })
exportedasync

Calls CreateCustomBudgetResource for each orphan. Returns recreatedMaterials, idRemap (old→new), and failurePreviousIds.

applyCustomMaterialRemapToDraft(draft, idRemap, recreatedMaterials, failurePreviousIds)
exported

Deletes failed previous ids from the draft; moves successful entries under the new device id; remaps materialId inside every GT device line.

remapTemplateMaterialIds(templates, idRemap)
exported

Same materialId remap, but for in-memory UI template rows (used on Refresh Materials before template reconcile).

Orphan recreate

recreateOrphanTemplates.ts

Recreates Group Templates that exist in LS but were deleted on the server. Only devices that still exist in Project Materials are reattached. Remaps draft template ids and GI keys to the new server ids.

Functions

toSourceRow(orphan, subclassItems)
internal

Builds a temporary UI template row from the orphan draft for recreate steps.

recreateOrphanTemplates({ projectId, orphans, subclassItems, createBlank, updateTemplate, createDevice, deleteTemplate })
exportedasync

For each orphan: create blank template → update parent fields → create remaining devices. If parent update fails, deletes the blank and records failure. Returns recreated templates + id remap + failures.

applyOrphanRemapToDraft(draft, idRemap, recreatedTemplates, failurePreviousIds)
exported

Removes failed template ids (and their GI keys); moves successful drafts under the new template id; remaps GI keys via remapInstanceDraftKeys.

Mode A push

syncDraftToApi.ts

After UI has the merged LS+API values, push per-row cumulative updates to the backend. One material → one PATCH. One template → parent update + device create/update/delete. Does not wait for empty/required fields — syncs whatever is currently available.

Functions

materialNeedsSync / templateParentNeedsSync
internal

Diff helpers: only emit API calls when UI differs from the API baseline.

syncDraftToApi({ ...deps })
exportedasync

Runs material PATCHes and template parent/device mutations in parallel (Promise.allSettled). Collects failures without aborting the whole batch. Returns failure lists + failed id sets.

revertFailedMaterialsToApi(materials, apiMaterials, failedMaterialIds)
exported

For materials that failed sync, restore UI fields from the API snapshot. LS draft is left intact for retry.

revertFailedTemplatesToApi(templates, apiTemplates, failedTemplateIds)
exported

Same for templates, but preserves session instances and isExpanded (not API fields).

Shared helper

subclassIds.ts

Small helpers used across reconcile / draft build / sync for converting between subclass names (UI Select values) and subclass ids (API / LS draft values).

Functions

resolveSubclassIdByName(subclassName, subclassItems)
exported

Name → subClassId, or null if blank/unmatched.

resolveSubclassNameById(subclassId, subclassItems)
exported

Id → display name (via resolveSubclassName), or null.

isSubclassIdValid(subclassId, subclassItems)
exported

null is treated as valid (unassigned). Otherwise true only if the id exists in the current subclass list.
